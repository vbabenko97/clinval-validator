# Output formats

Use these structures when the user asks for a brief, critique, or redesign instructions rather than a finished deck.

## Slide-by-slide design brief

Use this structure:

# Deck design brief

## Assumptions

State audience, objective, source material used, and any style assumptions.

## Design system

Describe format, typography, color palette, layout grid, icon/photo style, chart style, and accessibility approach.

## Slide plan

For each slide:

### Slide [number]: [claim-led title]

- purpose: what this slide must accomplish
- layout: selected slide archetype and arrangement
- content: main text, data, or visual elements
- visual treatment: chart, diagram, cards, screenshot, callouts, etc.
- notes: speaker notes, caveats, or production considerations

## Risks or missing inputs

List missing data, weak claims, or content that needs verification.

## Redesign review

Use this structure for existing decks:

# Deck redesign review

## Overall diagnosis

Summarize narrative, design, and accessibility quality.

## Priority fixes

Group issues by impact:

- high impact: affects comprehension, decision, or credibility
- medium impact: affects polish or flow
- low impact: formatting and minor consistency issues

## Slide-by-slide recommendations

For each relevant slide:

### Slide [number]: [current or proposed title]

- issue: what is not working
- recommendation: what to change
- rationale: why it improves the slide
- production note: how to implement it in PowerPoint

## Final deck summary

When delivering a finished `.pptx`, keep the response concise:

- file link
- slide count
- source material used
- design choices
- assumptions
- limitations or missing assets
